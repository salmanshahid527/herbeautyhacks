# SEO setup

This doc describes what’s in place for crawlability and SEO.

## Site URL

Set the canonical base URL in `.env.local`:

```bash
NEXT_PUBLIC_SITE_URL=https://herbeautyhacks.com
```

No trailing slash. Used for sitemap, `robots.txt`, canonical URLs, and Open Graph URLs.

## Root metadata

- **metadataBase** – All relative URLs (OG images, etc.) are resolved against `NEXT_PUBLIC_SITE_URL`.
- **Open Graph** – `type`, `locale`, `siteName`, `title`, `description`, `images`.
- **Twitter** – `summary_large_image`, `title`, `description`.
- **Robots** – `index, follow` and same for `googleBot`.

## Crawling

- **`/robots.txt`** – Generated by `app/robots.ts`: allows `/`, disallows `/api/`, points to `/sitemap.xml`.
- **`/sitemap.xml`** – Generated by `app/sitemap.ts` (revalidated hourly):
  - Static: `/`, `/blog`, `/about`, `/contact`, `/shop`.
  - From WordPress: blog posts (`/blog/{slug}`), categories (`/category/{slug}`), and pages that map to static routes.

## Structured data (JSON-LD)

- **Root layout** – Organization + WebSite (with `potentialAction` SearchAction).
- **Blog post pages** – Article (headline, dates, author, image, publisher).

## Per-page SEO

- **Blog post** – `generateMetadata` sets `title` and `description`; canonical and Open Graph are set from the same base URL and slug.

## After deploy

1. Confirm `https://<your-domain>/robots.txt` and `https://<your-domain>/sitemap.xml` load.
2. Check sitemap includes WordPress posts/categories if the API is reachable.
3. Use [Google Rich Results Test](https://search.google.com/test/rich-results) or similar to validate JSON-LD.
